Chi tiết Kiến trúc: ToyStoreManagement

Báo cáo này cung cấp thông tin chuyên sâu về cấu trúc hệ thống Clean Architecture (Multi-Project Solution).

1. Bản đồ Phân lớp (Architecture Layers)

API Layer (Presentation)
Infrastructure Layer (Persistence & Reporting)
Application Layer (Business Logic)
Domain Layer (Core Entities & Interfaces)

2. Phân tích chi tiết từng tầng

Dự án: ToyStoreManagement.Domain (Core/Domain)

Vai trò: Trung tâm của toàn bộ hệ thống, độc lập hoàn toàn với các tầng khác.
  • Entities: Các thực thể dữ liệu chính (Product, Order, InventoryReceipt, ...).
  • Interfaces: Định nghĩa các hợp đồng (Contracts) cho Repository (ví dụ: IRepository).
  • Enums: Định nghĩa các trạng thái, loại hình xuyên suốt hệ thống.

Dự án: ToyStoreManagement.Application (Core/Application)

Vai trò: Xử lý nghiệp vụ, chuyển đổi dữ liệu (DTOs) và hỗ trợ tính toán.
  • Services: Chứa logic nghiệp vụ thực sự (ví dụ: `SaleService` tính toán đơn hàng, `ProductService` xử lý catalog).
  • DTOs: Đối tượng chuyển dữ liệu qua lại giữa tầng API và Application.
  • Interfaces: Định nghĩa các Service Interfaces để API và Infrastructure phụ thuộc vào đó.
  • Helpers: Các tiện ích logic (CurrencyHelper chuyển số tiền sang chữ, EnumExtensions).

Dự án: ToyStoreManagement.Infrastructure (Infrastructure)

Vai trò: Triển khai kỹ thuật cụ thể (Storage, Third-party libs).
  • Persistence: `AppDbContext` (EF Core), cấu hình Oracle DB, triển khai các Repository thực tế.
  • ExternalServices: Triển khai các dịch vụ ngoại vi. Ví dụ: `ReportService` sử dụng QuestPDF để xuất báo cáo PDF và MiniExcel cho Excel.

Dự án: ToyStoreManagement.API (Presentation)

Vai trò: Điểm đầu vào (Entry point), tiếp nhận request và trả về response.
  • Controllers: Tiếp nhận API request, gọi Service và trả về DTO.
  • Configuration: `Program.cs` cấu hình Dependency Injection, Swagger, Middleware, và appsettings.

3. Các quyết định kiến trúc quan trọng

Vấn đề Giải pháp Kiến trúc Lợi ích
Phụ thuộc vòng Dependency Inversion Phá vỡ vòng lặp phụ thuộc (Service gọi Repository Interface, không gọi DbContext trực tiếp).
Hiệu năng Báo cáo Tách biệt service báo cáo Sử dụng thư viện chuyên dụng (QuestPDF) không ảnh hưởng tới logic CRUD.
Bảo trì Multi-Project Solution Đóng gói mã nguồn, dễ quản lý package NuGet, độc lập build.

4. Dòng phụ thuộc (Dependency Rule)

Quy tắc sống còn: Sự phụ thuộc chỉ đi từ ngoài vào trong:

API → Infrastructure → Application → Domain
